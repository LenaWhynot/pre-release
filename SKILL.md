# /pre-release

Проведи предрелизный аудит текущего проекта. Выяви блокеры, назови конкретные правки и отдай решение о выпуске владельцу проекта. Начни с проверок на чтение. Деплой, исправления, запуск миграций и запросы к боевым сервисам требуют отдельной команды.

1. **Уточни, что проверяешь.** Определи корень проекта, состояние рабочей копии и цель релиза. Используй абсолютный путь к папке, в которой лежит этот `SKILL.md`. Запусти из корня проекта:

   ```bash
   bash "<skill-dir>/detect_stack.sh"
   bash "<skill-dir>/scan_leaks.sh"
   ```

   Скрипты работают локально. Сканер выдаёт эвристические находки и сводку `SUMMARY`. Для красных и жёлтых строк проверь контекст. Не выводи значения секретов, содержимое `.env` и персональные данные в чаты, логи или отчёты.

2. **Пройди [чеклист](checklist.md) по коду.** Проверь, кто получает доступ к данным, серверную валидацию, SQLi/XSS, защитные заголовки, ограничения запросов, CORS и обработку ошибок. Для Supabase проверь RLS и политики, а при отсутствии доступа к ним пометь проверку как ручную. Сверь настройки с активной конфигурацией релиза.

3. **Проверь риски, которые есть в этом проекте.** Для вебхуков проверь подлинность входящих событий способом провайдера и идемпотентность повторной доставки. Для миграций, фоновых отправок и смены конфигурации проверь обратимость, объём накопившихся задач и обязательные переменные. Подробности для таких изменений есть в [зонах security-ревью](security-zones.md).

4. **Собери решение о выпуске.** Для каждой значимой находки дай `файл:строка` или основание, объясни последствия и конкретный следующий шаг. Красный блокер означает `FAIL`. Если нужную проверку невозможно выполнить, зафиксируй `NEEDS REVIEW` и укажи, как её завершить. Используй `PASS` только когда критичные применимые проверки выполнены и блокеров нет. Раздели подтверждённое, ручные проверки и пункты, которые здесь неприменимы.

По запросу сохрани отчёт в `.pre-release-report.md`. Оставь отчёт локальным и не добавляй его в коммит. Эвристический скан и чтение кода не заменяют проверку настоящих политик доступа, сценариев входа и готовности отката.
