# Чеклист security-ревью ветки — 10 зон по убыванию цены ошибки

Вопросы для проверки по коду. Выбирайте зоны, которые применимы к проекту.

## 1. Платежи (ошибка = чужие деньги)
- Подпись: HMAC по **сырым байтам** тела (не перепарсенный JSON), `crypto.timingSafeEqual`, длина сверяется первой, проверка — ДО чтения полей.
- Идемпотентность: транзакция Serializable (или блокировка строки), retry на `P2034`/`40001` и `P2002` с **ограничением** (×3), исчерпание → 5xx (пусть ретраят), не 200.
- Гонка двух вебхуков по одному заказу: второй видит `paid` и не выдаёт доступ/письмо повторно. Есть тест?
- Уникальные индексы на `providerOrderId`/`providerPaymentId`; чужая привязка → `rejected`.
- Сумма и валюта сверяются со **снимком покупки** (сделан при чекауте), не с ценой в БД. Что при скидке/промокоде?
- Сверьте коды ответа с правилами повторной доставки провайдера. На потерянное событие и ошибку проверки нужны разные реакции. Убедитесь, что ответственный узнает о платеже без выдачи доступа.
- Всё, что `await`-ится до ответа провайдеру (алерт, письмо) — с таймаутом и проглоченной ошибкой; общее время < таймаута провайдера.
- `refund`/`partial_refund`/`fraudulent`: что отзывают и у каких статусов; решение владельца записано.

## 2. Аутентификация и сессии
- JWT: `iss`/`aud`/`sub`, версия креденшелов; **старый токен → `null` → редирект на логин, не 500**.
- Magic-link: одноразовость атомарна (`GETDEL`), TTL, 64+ hex; ссылка не попадает в логи/реферер.
- CSRF: проверка Origin/Referer на **всех** мутирующих методах account/admin/auth/checkout.
- Найдите сравнения входящих секретов. Для HMAC и других секретов фиксированной длины проверяйте длину и используйте сравнение с постоянным временем.
- Куки: httpOnly/secure/sameSite; срок.
- Dev-роуты (`/api/dev/*`): двойной гейт `NODE_ENV=development` **и** явный флаг, иначе 404.

## 3. Вебхуки Telegram / почты (ошибка = бот встал или спам)
- Секрет: Telegram `secret_token` заголовок; почта — **тем же способом, что прописан у провайдера** по его актуальной документации.
- Дедуп: по `update_id` (лизинг в Redis с owner-токеном, TTL, release при исключении) / по `eventKey @unique` (P2002 → счётчик дублей, не 5xx).
- **Постоянная ошибка отправки (4xx: бот заблокирован, чат не найден) → подтвердить апдейт (200) + лог/алерт; временная (5xx, таймаут, 429) → 5xx.** Иначе Telegram ретраит один апдейт вечно.
- Redis недоступен → что? 503 (не терять) или 200 (терять) — решение записано.
- Новые nullable-колонки (`*ExpiresAt`) — что код делает с `NULL` у существующих строк: истёк / бессрочен / падает?

## 4. SSRF (ошибка = доступ во внутреннюю сеть)
- Приватные диапазоны v4 (10/8, 172.16/12, 192.168/16, 127/8, 0/8, 169.254/16, 100.64/10, multicast) и v6 (`::1`, `fc00::/7`, `fe80::/10`, **`::ffff:`-mapped v4**).
- Десятичные/восьмеричные IP — нормализует ли WHATWG `URL` до проверки; `localhost`, `0.0.0.0`.
- **DNS-пиннинг без TOCTOU**: резолв → проверка каждого адреса → коннект на тот же адрес через кастомный `lookup`.
- Редирект → полная повторная проверка; лимит редиректов; только 80/443; таймаут; лимит тела.
- Легитимные эмбеды (youtube/vimeo/kinescope/t.me) — по allow-list хостов, не сломаны. `data:` в MDX — вырезается? регрессия контента записана.

## 5. Файлы и аплоады
- Квота: `SELECT … FOR UPDATE` **в той же транзакции**, что и вставка записи.
- Файл на диск `wx` + rename; при сбое БД — удаление файла.
- Traversal: `..`, абсолютные, `\`, URL-encoded, NFD/NFC; имя на диске серверное (случайное).
- Тип — по **сигнатуре содержимого**, не по заголовку браузера; лимиты размер/число; выдача с `attachment` + `nosniff`.
- Авторизация «свой файл / свой поток / срок доступа не истёк».

## 6. Fail-fast env на старте
- Проверка в `instrumentation.ts` под `NEXT_RUNTIME === 'nodejs'`; проверьте на конкретной версии Next, что процесс завершает работу с ошибкой при отсутствии обязательной настройки. Используйте изолированный запуск без прод-секретов.
- Список переменных сверен с реальным использованием (`mailer.ts`, `alerts.ts`, `jwt.ts`, `redis.ts`); все нарушения одним списком; **значения секретов не печатаются**.
- Драйверы с дефолтом `console`/`memory` в проде запрещены. `TRUST_PROXY`-флаги — только при `expose` (не `ports`) + прокси перезаписывает XFF.
- Проверьте, где действует флаг: в приложении, драйвере или настройках аккаунта провайдера. Сопоставьте конфигурацию с фактическим поведением.

## 7. Admin-роуты
- В **каждом** `route.ts` проверка прав (`verifyAdminApi`/аналог) — пересчитать файлы и вызовы, не выборочно.
- Тело ограничено по размеру и глубине; невалидный JSON → 400/413, не 500.
- Не удалили ли проверку прав, добавляя валидацию.

## 8. Миграция фреймворка внутри ветки (Next 15 / React 19)
- `grep -rn 'params\.\|searchParams\.' src/app` без `await` → 0; `cookies()`/`headers()`/`draftMode()` только с `await`; `useFormState` → `useActionState`.
- `next.config`: CSP не ломает картинки (`img-src https: data:`), эмбеды (`frame-src`), mermaid (inline styles), свои шрифты.
- Мажоры в `package.json` — пин без caret? `engines.node` совпадает с образом.

## 9. Rate-limit / cron / analytics
- Redis упал → страховочный лимитер в памяти с теми же лимитами (не «без лимита»).
- `getClientIp`: без доверия прокси — один бакет на всех (самоDoS); с доверием — прокси обязан перезаписывать заголовки.
- Cron-роуты под секретом (timing-safe); аналитику нельзя накрутить без лимита.

## 10. Репозиторий и образ
- Логи аудита/чужие пути/`.env` в git → нет. `.dockerignore`: `docs`, `*.md`, `.env*`, тесты, ключи.
- Линт и `tsc` покрывают новые расширения (`.mts`); `tsconfig.include`.
- Образ из **того же коммита**; внутри нет тестов/`docs`/`.env*`; каталог аплоадов принадлежит uid процесса; `tsx` и seed-скрипты — если их зовёт `DEPLOY.md`, они должны быть в образе или запускаться из builder-стадии.
- `DEPLOY.md` знает новые env и миграции; внутренние отчёты об уязвимостях хранятся в закрытом месте с доступом для ответственных за исправление.

## Формат отчёта ревьюера
Вердикт READY/NOT READY · починено (SHA · файл:строка · дефект · чем опасен) · нашёл-но-не-чинил
(решает владелец) · проверено по зонам одной строкой · коды выхода typecheck/lint/тестов.
Стоп-условие цикла: «дефектов не найдено, коммитов нет».
